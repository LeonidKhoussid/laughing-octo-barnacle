# API-контракт автопроверки — AlfaGen PII Gateway

## Статус: VERIFIED (официальный контракт реализован и протестирован)

Официальное Приложение A получено из `ds.pdf` (стр. 6–7), Приложение B — стр. 8–9.
Контракт `POST /process` реализован в `app/api/autocheck.py` и проверен тестами
и живым HTTP-запросом. Совместимость подтверждена фактическими контрактными тестами.

## Официальный контракт (Приложение A)

```
POST /process
Content-Type: application/json
{ "payload": "<строка>", "payload_id": "<идентификатор>" }
  → 200
{ "result": "<строка>" }
```

- Один эндпоинт обрабатывает и маскирование, и демаскирование.
- Направление определяется по `payload_id` как ключу корреляции «маскирование → демаскирование».
- Первый запрос с новым `payload_id` — маскирование (payload = исходная строка) → вернуть маску и запомнить соответствие.
- Второй запрос с тем же `payload_id` — демаскирование (payload = ваша маска) → вернуть исходную строку.
- Ответ всегда: `{"result": "…"}`.
- 429 допустим под нагрузкой (с Retry-After); 4XX/5XX — ошибки.

## Маршрутизация (идемпотентная, безопасная к ретраям)

Реализована **контентная** маршрутизация (не слепой toggle), чтобы ретраи не ломались:

| Вход | Результат |
| --- | --- |
| Новый ID + исходный текст | Маскирование; mapping фиксируется до успешного ответа |
| Тот же ID + тот же исходный текст | Та же маска (mask replay) |
| Тот же ID + точная возвращённая маска | Восстановление исходного текста (demask) |
| Повторный demask (та же маска) | Тот же исходный текст (demask replay) |
| Тот же ID + иной текст | Безопасная ошибка 409, без перезаписи |
| Исходный == маска (нет ПД) | Обрабатывается без ложного конфликта |

## Требования надёжности (Приложение B)

- Таймаут одного запроса — **10 секунд** (ответ дольше считается неответом).
- Ретраи — до 2 на запрос (итого до 3 попыток); эндпоинт идемпотентен по `payload_id`.
- **429** (Too Many Requests) допустим под нагрузкой; система применит ожидание и ретраи (учитывается Retry-After).
- Стоп при недоступности: после **5 невалидных запросов подряд** прогон останавливается (429 невалидным не считается и счётчик не сбрасывает; успешный ответ сбрасывает счётчик).
- Нагрузка: ~5 минут, целевой RPS 1000, все категории, элементы датасета переиспользуются.
- Целевое latency — не более 1 c (ориентир, не жёсткий лимит). Не путать с 10-секундным таймаутом.
- HTTP и HTTPS (в т.ч. самоподписанный) поддерживаются; проверка идёт с `ssl_verify=false`.

## Метрика качества (Приложение B)

Официальная метрика — **нормированное span-based расстояние Левенштейна** в [0..1].
Прямая проверка сравнивает возвращённую маску с эталонной; обратная — возвращённый
исходный текст с исходной строкой датасета. Локальные диагностические метрики
(per-category P/R/F1, concealment recall, overmask rate) помечаются отдельно как
LOCAL DIAGNOSTIC и не выдаются за официальную формулу. Правила выравнивания и
направление скрытого скоринга не выдумываются.

## Самопроверка формата (стр. 9)

Внешний сервис `https://process-test.holydev.space/process` — **только** эталон
формата обмена. Он не является нашим развёртыванием и не валидирует качество
детекции. Реальные персональные данные и секреты ему не отправляются.

## Реализация и тесты

- `app/api/autocheck.py` — официальный адаптер `{payload, payload_id} → {result}`.
- `tests/integration/test_api.py::TestAutocheck` — контрактные тесты (mask, demask,
  mask replay, demask replay, conflict, no-PII, 429+Retry-After).
