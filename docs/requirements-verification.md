## Функциональные требования

| Требование | Реализация и проверка | Ограничение |
| --- | --- | --- |
| Все 17 типов ПД | Реестр детекторов и 19 новых примеров в `tests/fixtures/requirements_detection_cases.json`; unit-проверки и `tests/integration/test_required_fields.py` через настоящий model-enabled `/process` | Конечный набор примеров не доказывает распознавание всех вариантов |
| Публичная информация и частные записи | Локальные RuBERT NER + mDeBERTa NLI, контекст конкретного упоминания, приоритет личной записи; контрастные публичные/частные примеры | NLI оценивает контекст, не проверяет истинность публичности; остаются неоднозначные биографии и адреса |
| Регистр, порядок дат, даты словами, паспортные разделители | Числовые и словесные даты, `04.13.1990`, `2015.13.04`, склонения ФИО, отдельные значения серии/номера | Неоднозначные даты без контекста не получают выдуманной семантики |
| Адрес и отдельные компоненты | Страна, индекс, город, улица, дом, квартира; чувствительные значения в порядке исходного текста | Служебные слова сохраняются; целый адрес в старом эталоне может дать расхождение границ без утечки значения |
| Точное демаскирование | Один план замены, непрозрачные токены, соответствие в Vault; Unicode, повторы, конфликт и round-trip | TTL/ёмкость ограничены; MemoryVault теряет записи при рестарте |
| Расширение списка | Config-driven regex detector + реестр; новый тип не требует изменения ядра | Модель не обучается автоматически на новом типе |
| Ограниченный список систем | Consumer policies, enabled, namespace, API key; отдельное исключение autocheck | `/process` намеренно публичен для тестера, остальные защищённые профили требуют ключ |
| Настройка типов и демаскирования | `configs/consumers.yaml`, валидация до активации, запрет unmask перепроверяется | UI-изменения действуют в одном процессе; для постоянного/multiworker изменения нужен файл и общий рестарт |
| Инструкция до 5 предложений | Пять пронумерованных предложений в README | Секреты не входят в исходный ZIP |
| Логи по этапам и типам | Серверный request ID, vault/detect/resolve/mask/unmask/result/errors, счётчики типов; canary-тесты | Записываются выполненные этапы; исходные значения, токены и payload ID не логируются |

## §7: сдача и готовность сервера

Необходимы оба артефакта: ZIP исходного кода и URL запущенного сервиса.
`scripts/package_submission.py` исключает `.env`, виртуальные окружения,
`node_modules`, сборки, веса моделей, датасеты, архивы и медиаданные.
Docker собирает React и скачивает проверенные по SHA-256 модели в отдельном
кэшируемом слое; исходный ZIP не содержит эти веса.

Публичное развёртывание `http://201.34.146.180:8000/` было доступно при предыдущем
smoke-review. Локальные изменения не загружаются на сервер автоматически.
Повторная внешняя проверка новой версии возможна после обновления по
`docs/server-deployment.md`; параметры сервера со слов пользователя: 4 CPU,
8 GB RAM, 80 GB NVMe. Скорость на этом сервере нельзя выводить из теста Mac.

## Приложение A

`POST /process`: `{"payload":"...","payload_id":"..."}` →
`{"result":"..."}`. Новый ID маскирует; тот же исходный текст повторно получает
ту же маску; возвращённая маска с тем же ID восстанавливает исходный текст;
повтор восстановления сохраняет результат. Конфликт даёт 409 и не перезаписывает
контекст. Пустая строка/текст без ПД не переключаются ошибочно между режимами.

## Приложение B

- Клиентский таймаут — 10 с; серверный бюджет по умолчанию 9 с, включая очередь.
- Реальное превышение бюджета `/process` возвращает 429 с `Retry-After: 1`.
- Нативная работа после timeout сохраняет слот до завершения и может зафиксировать
  соответствие для безопасного ретрая; отменённая работа в очереди не запускается.
- Два ретрая и остановка после пяти невалидных запросов — поведение тестера;
  429 не увеличивает и не сбрасывает этот счётчик, успех сбрасывает.
- Приложение B описывает около пяти минут, все категории, цель 1000 HTTP RPS;
  маскирование и восстановление считаются отдельными запросами. В чате организатор
  уточнил постепенное повышение нагрузки, среднее около 330 и пики 1000 RPS;
  точное расписание не опубликовано (`docs/chat-review-2026-09-23.md`, #666/#685).
  Фиксированная интенсивность генератора не выдается за воспроизведение этого расписания.
- Локальные span/character-метрики не выданы за скрытый нормированный
  span-based Levenshtein. Постоянные 429 считаются недостаточной ёмкостью.

## Безопасность и нормативные требования

Технически проверяются изоляция потребителей, ключи, запрет демаскирования,
минимизация данных в логах/метриках, AEAD для RedisVault, TTL, ошибки без ПД,
защита отправки провайдеру и новых ПД в его ответе. Runtime не отправляет текст
во внешнюю модель. Демо использует явно обозначенный имитатор LLM.

Полное соответствие законодательству РФ и требованиям ЦБ не подтверждается
тестами приложения: для банковского внедрения нужны согласованные роли доступа,
модель угроз, сроки хранения/удаления, защищённый транспорт, размещение данных,
управление ключами и эксплуатационные процедуры. HTTP допускается условиями
хакатона, но текущий публичный демонстрационный URL не является готовым
банковским контуром для реальных персональных данных.


Полный JSON ограничен до разбора схемы, включая неизвестные поля и chunked-body:
до 6 × лимит текста + 4096 байт для экранирования Unicode. Отдельный лимит
декодированного текста сохраняется; чрезмерное тело получает безопасный 413.
