# Контекст, объяснения и стабильность — 23 сентября 2026

## Что изменилось

Контекстный детектор отдельно проверяет признаки частной информации перед
разрешением публичного упоминания. Тема «искусство» или «наука» сама по себе
не отменяет защиту личной записи. Явные заявки, закрытые списки и непубличные
журналы защищаются до NLI. Для биографических справочников сохранена отдельная
политика: сведения о человеке в справочнике не становятся частной записью
только из-за положительного ответа общей NLI-гипотезы.

Начальная приватная и первая публичная гипотезы выполняются одним пакетом.
При отказе обязательной модели API по-прежнему не возвращает необработанный
текст. Ускоренный кандидат не включён в основной pipeline.

Распознавание имён поддерживает Unicode, диакритику, апострофы и транслитерацию
рядом с явными обозначениями человека или поля имени. Добавлены получатели
и заказчики без расширения словаря фамилий. Личные адреса распознаются также
после «из дома» и с обозначением переулка. Служебные слова адреса сохраняются.

В React появился свёрнутый сценарий «Одно имя — два контекста». Он выполняет
два настоящих запроса к существующему Action A и показывает сохранённое
публичное упоминание Бернарда Шоу и скрытое имя в вымышленной личной записи.
Объяснения берутся из текущих `Detection`: NER, NLI, правило исторического
упоминания, явная личная запись и неопределённость различаются. Проценты
уверенности не показываются. Для объяснений модель повторно не вызывается.
В журналы и отчёт проверки не добавляются исходные значения или тексты.

## Нативные сбои исследовательского процесса

23 сентября в 14:49:38 и 14:50:17 MSK упали два отдельных экспериментальных
процесса Python 3.11 (PID 94585 и 95428). Оба crash report показывают
`SIGBUS / EXC_ARM_DA_ALIGN`: PyTorch 2.8 → `libtorch_cpu` → Apple Accelerate
BLAS при вычислении Bert pooler. Это не сбой ONNX Runtime: первоначальная
гипотеза об ORT была опровергнута нативным стеком.

Эксперимент остановлен. `artifacts/tiny_nli_lab.py` запрещает экспорт на
macOS до импорта Torch/ORT и предлагает выполнять экспорт на Linux.
Проверено, что защитный отказ не импортирует нативные библиотеки. Библиотека
PyTorch не добавлялась в зависимости приложения. Исследовательский кандидат
сохранён отдельно; его качество и производительность не проверены, лицензия
fine-tune не установлена, в manifest работающего сервиса он не включён.
Статус и происхождение: `artifacts/tiny-nli-experiment-status.json`.

Работающий backend использует `.venv`, Python 3.14 и ONNX Runtime 1.30.0.
Во время указанных двух сбоев он продолжал отвечать. Нативная проверка
NER/NLI и нормального выхода Python включена в pytest. После остановки
эксперимента новых macOS crash report в ходе проверок не появилось.

## Производительность и незакрытые задачи

Дополнительная проверка частного контекста увеличивает вычислительную
стоимость. Текущий короткий HTTP-прогон сохранён в
`artifacts/context-improvements-throughput.json`, условия — в
`artifacts/context-improvements-server.json`. Это один CPU worker, MemoryVault,
генератор на том же Mac, 10 секунд, concurrency 8, смесь private/public/mixed
с восстановлением. Он не доказывает 1000 RPS, нагрузку на Linux или 100k-token SLA.

Фактический последний результат: 1148 корректных HTTP-ответов, из них 1140
внутри 10-секундного окна, 114,0 успешных RPS; p95 301,18 мс, p99 344,84 мс;
ошибок HTTP и содержимого нет. До объединения начальных гипотез текущая
версия с дополнительной проверкой приватности показала 71,7 RPS
(`artifacts/context-improvements-throughput-unbatched.json`). Это короткие
локальные замеры, а не гарантированный выигрыш на другой машине. Ранее
зафиксированные 207 RPS относятся к прежней политике без нового NLI-veto.

Цель 1000 RPS остаётся незакрытой. Следующий шаг — обученный компактный
классификатор отношений с независимой калибровкой и сравнением качества,
покрытия и задержек. Повторять падающий Torch-экспорт на этом Mac нельзя.
Публичное развёртывание, актуальный исходный ZIP и чистая установка в этом
проходе не выполнялись.
